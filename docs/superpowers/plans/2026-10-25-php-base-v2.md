# php-base v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the tested prototype into php-base v2 on `feat/php-base-v2`. That means:
- an s6-supervised PHP base image for 8.2–8.5, built on a clean Alpine;
- nginx tuned for Traefik;
- CI that always builds the newest upstream;
- copy-to-start examples;
- a tidy repo.

**Architecture:**
- **Images.** Extensions compile on the official `php:<line>-fpm-alpine` image. The runtime image is assembled on a clean `alpine:<same minor>`. `-dev` adds the PHP sources, Composer and the debuggers.
- **Inputs.** A resolver script pins every upstream input on every run.
- **Tests.** Shell suites (runtime, dev, frameworks, examples) gate every change.
- **CI.** GitHub Actions builds per architecture on native runners, tests the pushed digest, and publishes per PHP line.

**Tech stack:**
- Docker / BuildKit (Dockerfile syntax 1.7), Alpine 3.24;
- PHP 8.2–8.5 from the docker-library images;
- nginx 1.30, s6 2.15, tini;
- busybox `sh` for scripts inside the image; bash, jq and curl for host scripts and tests;
- GitHub Actions, Renovate;
- Traefik v3, wollomatic/socket-proxy.

**Spec:** `docs/superpowers/specs/2026-10-24-php-base-v2-design.md` (approved). Its §6 and §6b are binding. Section references below (§…) point into it.

## Global Constraints

**Lines and tags**
- PHP lines 8.2, 8.3, 8.4 and 8.5 are stable. 8.6 is a pre-release canary: it is allowed to fail and gets only `8.6-rc` and `8.6-rc-dev`.
- The published image is `docker.io/achelesstech/php-base`. Local builds are `local/php-base:X.Y` and `local/php-base:X.Y-dev`.
- Tags:
  - `X.Y`, `X.Y.Z`, and `X.Y.Z-YYYYMMDD` (or the next free `X.Y.Z-YYYYMMDD.N`);
  - `latest` for the line marked `"latest": true`;
  - a `-dev` twin of each (`latest` → `latest-dev`);
  - **no `X.Y-alpineA.B`**.

**Image contents**
- **Runtime base:** `alpine:<minor>@sha256:…`, where `<minor>` comes from `/etc/alpine-release` inside the resolved `php:<line>-fpm-alpine@sha256:…`.
- **Labels:**
  - the OCI set, with `org.opencontainers.image.base.name`/`.base.digest` naming the Alpine image;
  - `io.github.achelesstech.php-base.upstream-image`, `.upstream-digest`, `.php-version`, `.alpine-version`, `.variant`.
- **User:** `www-data` 1000:1000, home `/home/www-data` with mode 0750.
- **Processes:** PID 1 is `tini`, and every process runs as `www-data`.
- **Writes:** only under `/tmp`. The runtime dir `/tmp/php-base` is wiped and re-rendered at every start. Config, scripts and s6 service definitions are root-owned.
- **Sockets and ports:**
  - public port 8080;
  - internal status listener `127.0.0.1:8081`;
  - PHP-FPM socket `/tmp/php-base/php-fpm.sock`, mode 0660;
  - nothing listens on 9000.

**Hardened run flags** (used by the tests and the examples):

```
--read-only --tmpfs /tmp:rw,noexec,nosuid,nodev,size=256m --cap-drop ALL
--security-opt no-new-privileges --pids-limit 256 --memory 1g
```

**Size ceilings.** These apply to the amd64 runtime image, uncompressed. MB = 10^6 bytes. They are stored in `versions.json` as `max_size_mb`.

| Line | Ceiling |
|---|---|
| 8.2 | 175 MB |
| 8.3 | 178 MB |
| 8.4 | 180 MB |
| 8.5 | 198 MB |

**Defaults**

| Setting | Default |
|---|---|
| `NGINX_WORKER_PROCESSES` | `2` |
| `NGINX_GZIP` | `0` |
| `NGINX_ACCESS_LOG` | `off` |
| `NGINX_FASTCGI_READ_TIMEOUT` | `300s` |
| `keepalive_timeout` | `120s` |
| `keepalive_requests` | `10000` |
| `FPM_MAX_CHILDREN` | `auto` |
| `FPM_WORKER_MEMORY` | `64M` |
| `FPM_REQUEST_TERMINATE_TIMEOUT` | `300s` |

**Shell rules**
- Every Dockerfile `RUN` that contains a pipe starts with `set -eux -o pipefail`.
- No `SHELL` instruction.
- Never assert with `! pipeline`, because `set -e` ignores it.
- Never end a pipefail pipe in `grep -q`: capture the output first.
- busybox `find` takes `-user`/`-group`, never `-uid`/`-gid`.

**Tests**
- Every container, network and volume a test creates carries a `php-base-test=…` label, and cleanup uses `docker rm -f -v` plus labelled-volume removal.
- Builds run one at a time, and at most one framework or example test runs at a time. The host has 7 GB RAM.

**Prototype rule.** Where the prototype (frozen at `.work/prototype/` in Task 1.1) already solves something the spec doesn't change, keep its solution.

**Git**
- Branch `feat/php-base-v2`, one commit per task.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never push.

### Task 1.4: Resolver v2 and local build arguments

**Files:**
- Create: `scripts/lib/guards.sh`, `scripts/build-args.sh`, `test/scripts/guards.test.sh`, `test/scripts/resolve.test.sh`

**Interfaces.** `scripts/lib/guards.sh` is sourceable bash with no side effects:

| Function | Result |
|---|---|
| `php_guard UPSTREAM NEWEST NEWEST_DATE TODAY` | Prints `ok`, `warn:<msg>` or `fail:<msg>`. `NEWEST_DATE` is php.net's `date` field (e.g. `21 Oct 2026`); `TODAY` is `YYYY-MM-DD`. Equal versions → `ok`. Empty `NEWEST` → `warn` (php.net unreachable). Different and more than 3 days after `NEWEST_DATE` → `fail`. Otherwise → `warn` |
| `alpine_guard IMAGE_MINOR LATEST_MINOR LATEST_FIRST_DATE TODAY` | `warn:<msg>` when `LATEST_MINOR` > `IMAGE_MINOR` (version compare) and more than 14 days have passed since `LATEST_FIRST_DATE`; otherwise `ok` |
| `next_build_tag BASE [EXISTING…]` | `BASE` if it isn't among `EXISTING`; otherwise `BASE.N` with the smallest free N ≥ 2 |

**`scripts/resolve-matrix.sh [--only L,…] [--include-eol] [--date YYYYMMDD] [--local]`** prints `lines=`, `build=`, `failed=`, `composer=` and `date=`.
- **`lines[]` keys, exactly:** `line, prerelease, upstream, digest, from, php_version, alpine, alpine_full, alpine_image, alpine_digest, build_tag, tags, dev_tags, max_size_mb, frameworks`.
- **`build[]`:** each line × each platform, plus `platform`, `arch`, `runner`.
- **`failed`:** a JSON array of `{line, reason}`.
- **A guard `fail`:**
  - removes the line from `lines` and `build`;
  - adds it to `failed`;
  - emits `::error::`.
- **`--local`:**
  - turns `fail` into `warn`;
  - sets `build_tag` to `<php_version>-local`;
  - never contacts Docker Hub's tag API.
- **Data sources:**
  - Alpine data: `https://alpinelinux.org/releases.json`. Use `latest_stable` (e.g. `v3.24`); the first date is the minimum `date` among that branch's `releases`.
  - Tag existence: `${HUB_API:-https://hub.docker.com}/v2/namespaces/achelesstech/repositories/php-base/tags/<tag>`. 200 means the tag exists, 404 means it's free, and anything else → exit 1 with `cannot check existing tags on Docker Hub`.
- **New warnings:**
  - a pre-release line whose GA tag `php:<line>-fpm-alpine` already exists;
  - an active branch at `https://www.php.net/releases/active.php` (keys under each major) that `versions.json` doesn't list.

**`scripts/build-args.sh LINE`** prints one `--build-arg K=V` per line, for:

```
PHP_VERSION PHP_IMAGE ALPINE_IMAGE COMPOSER_IMAGE UPSTREAM_IMAGE UPSTREAM_DIGEST
PHP_FULL_VERSION ALPINE_FULL_VERSION BASE_NAME BASE_DIGEST BASE_VERSION
PKG_CACHE_BUST BUILD_DATE VCS_REF ALLOW_MISSING_DEV_EXTENSIONS
```

| Argument | Value |
|---|---|
| `BASE_NAME` | `docker.io/library/alpine:<minor>` |
| `BASE_VERSION` | `<php_version>-local` |
| `BUILD_DATE` | from the environment if set |

The resolver's line object is cached in `.cache/resolve/<LINE>-<YYYYMMDD>.json` and reused the same UTC day, unless `REFRESH=1`.

**`make build PHP=X.Y`** passes one identical argument list to both the runtime and the dev build.
